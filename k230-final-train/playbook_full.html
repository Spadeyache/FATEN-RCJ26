Competition Playbook — 詳細版 (with simulation) 🔬

各ステップの中身・コンテナ(CD)とのやり取り・量子化シミュレーションでの評価まで。
ふだんはシンプル版 playbook_competition.html で十分。すべて k230-final-train\ 内で実行。

★ワンコマンドふだんはこれ

raw_export\ にエクスポートを入れてから1行。整理→学習→export→kmodel(ベスト)→report→deploy。
CD: ホストで organize → k230d-train(GPU)で学習/export → k230-nncase(2.11)で変換。
.\competition_run.ps1 -Name victim_v2 -Epochs 100
⚠ kmodel は nncase 2.11 製（uint8でほぼ無劣化）。実機 K230D の CanMV ランタイム SDK が 2.11 互換か確認してから本番採用すること。

📸 PTQ 校正画像の準備（当日データ推奨）

PTQ は校正画像から量子化レンジを決めるので、実機が見る分布に近いほど精度が出る。当日の写真で校正するのが理想。

何枚: 16〜30枚（既定8は最小限。多さより代表性。50枚超は効果薄）
どんな: 当日のカメラ・照明・フィールドで撮影／各クラス(Dead/Live/Point)を含める／距離・角度・明るさをばらけさせる（近遠・明暗・正面斜め）／複数物体や背景だけの画像も少し／ラベル不要
避ける: 全部同じ構図、実機と全然違う画像
どこに置く: datasets/<Name>/calibration/ に入れるだけ → 自動で使われる（学習に影響なし・add_dataでも消えない）。優先順位は -CalibDir > calibration/ > val/images。 
# 明示指定したい場合:
.\convert_model.ps1 -Name victim_v2 -CalibDir datasets/victim_v2/calibration -CalibSamples 24

個別ステップ（中身を理解したい時）

0Docker Desktop を起動

docker info が通ればOK（1〜3分）。

1add_data — 写真追加 + train/val 分割（クラス一致確認）

raw_export\ 内の全エクスポートを結合（旧+新、重複除外）。各 classes.txt が一致するか検証してから分割。
CD: ホストの py -3 のみ（数秒）。中身は k230_pipeline.py organize。
.\add_data.ps1 -Name victim_v2

2train_model — 学習 + ONNX export GPU

datasets/victim_v2 で YOLOv8n 学習（100ep ≈ 18分, RTX3050）→ runs/victim_v2/weights/best.pt → models/best_640x480.onnx。-SkipTrain で学習を飛ばし export だけ。
CD: k230d-train(PyTorch+ultralytics, --gpus all)。フォルダを /workspace にマウント、終了で破棄。
.\train_model.ps1 -Name victim_v2 -Epochs 100

3convert_model — ONNX → kmodel(ベスト) + report + deploy nncase 2.11

検証済みベスト = NoClip uint8/uint8。コンパイル約15秒 + シミュレーション検証。出力 deploy/best.kmodel + report.html。
CD: k230-nncase。opencv を起動時に入れ、シミュレータが float ONNX と比較して cosine/conf_delta を表示。
.\convert_model.ps1 -Name victim_v2

シミュレーションで評価する 🔬 (with simulation)

kmodel をシミュレータで float ONNX と突き合わせ、量子化劣化(cosine/conf_delta)を測る。実機なしで精度を確認できる。

A量子化5設定を総当り（30枚で評価）

5設定（0=NoClip u8/u8, 3=Kld u8/u8, 1=NoClip u8/i16, 4=Kld u8/i16, 5=Kld i16/u8）を作り、各30枚で cosine・conf_delta・サイズを比較。基準「cosine≥0.999 → 最小サイズ → conf_delta」で最良を best_model/searched/ に保存。約60〜75分。
CD: k230-nncase。5回コンパイル＋シミュレーション。各結果は output/search/*/sim.json。
.\convert_model.ps1 -Name victim_v2 -Search -EvalLimit 30

Bランキング基準を変えて再選定（再コンパイル不要・数秒）

既存の sweep 結果(sim.json)から winner を選び直すだけ。基準を変えた時に高速。
CD: ホストの py -3 のみ（JSON を読むだけ・nncase 不要）。
py -3 k230_pipeline.py rerank --onnx models/best_640x480.onnx --img-width 640 --img-height 480

C1枚だけ手早く検証（プリセット, 少枚数）

ベスト設定を少ない枚数で素早くシミュレーション確認したい時。-EvalLimit を下げる。
CD: k230-nncase。コンパイル15秒 + 数枚のシミュレーション。
.\convert_model.ps1 -Name victim_v2 -EvalLimit 3

D複数の学習済みモデルを比較

-Name を変えて回し、各 report.html を別名保存して mAP・kmodel cosine・サイズで比較。
CD: 各回でワンコマンド。report.html は上書きされるので退避する。
.\competition_run.ps1 -Name victim_a -Epochs 80
Copy-Item report.html report_victim_a.html
.\competition_run.ps1 -Name victim_b -Epochs 120
Copy-Item report.html report_victim_b.html

指標の読み方

cosine（vs float ONNX, 1.0で一致）— 1に近いほど量子化劣化が小さい。2.11では全設定 ≥0.999 で飽和。
conf_delta（kmodel − float の検出信頼度差）— 0に近いほど良い。Kld はやや下がる傾向。
size — 実機128MBなので小さいほど良い。int16重みは約2倍。
sim ms — CPUシミュレータ速度であり実機KPU速度ではない（速度比較は size と compile を見る）。
