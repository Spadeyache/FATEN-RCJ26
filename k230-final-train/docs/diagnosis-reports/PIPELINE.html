How a single image becomes coloured boxes on screen

This is the full path a frame travels on the K230 board, from camera/JPG to the rectangles drawn around silver and black objects. It applies to both det_image_yolov8.py (one image off disk) and det_live_xy_yolov8.py (camera frames in a loop). They share preprocessing and decode logic; the only differences are the source (file vs sensor) and what happens with the result (save jpg vs send UART packet).

Why grayscale + histeq? The model was trained on greyscale photos that had their contrast stretched with histogram equalization (basically: spread dark pixels darker and bright pixels brighter so detail in shadows is visible). To get accurate predictions the input you feed the trained model has to look like the inputs it was trained on. So every frame, regardless of source, is forced through the same grayscale + histeq + 3-channel-replicate steps.
1
Source CPU JPG file or one sensor frame
A single image arrives. It can be a colour photo or a greyscale frame; could be 640×480 or any size.
▼
2
To grayscale collapse RGB into one channel
If the image is colour, average/weight the R,G,B planes into a single brightness plane. Now each pixel is one number 0–255.
▼
3
Histogram equalization (histeq) stretch contrast to the trained distribution
Remap pixel intensities so the dark/bright ranges fill the full 0–255 span more evenly. Without this, a dim photo would look different from training data and the model would under-perform.
▼
4
Replicate to 3 channels R = G = B = the grayscale plane
The model's input layer expects 3 channels (it was trained when the dataset stored grayscale photos as RGB JPGs with all three planes equal). So we copy the single plane into slots R, G, B.
▼
5
Letterbox to 640 × 480 resize with aspect-ratio preserved, gray pad 114
The model expects exactly 640 wide × 480 tall. If the source is a different shape, it's scaled by the largest factor that fits inside the box and the leftover strip is filled with grey (value 114). This is done by the K230's ai2d hardware unit. Output layout is uint8 tensor (1, 3, 480, 640).
▼
6
KPU runs the kmodel accelerator ~3 MB int16-activation YOLOv8n
Internally divides the uint8 input by 255 → float [0,1], runs a neural network (a stack of small convolutions + a detection head), and writes one output tensor of shape (1, 6, 6300):
rowmeaning
0box center x (pixels in 640×480 model space)
1box center y
2box width
3box height
4"silver" class confidence (already sigmoid'd, 0–1)
5"black" class confidence
The 6300 columns are 6300 candidate detections — three different grid sizes overlaid on the image (80×60 + 40×30 + 20×15 = 6300). Most of these candidates are noise and will be thrown away.
▼
7
Decode the 6300 candidates pick a class + threshold by confidence
For each of 6300 columns: compare row 4 vs row 5, pick the larger as the class, that value is the score. Drop the column if score < CONF_THRESHOLD (default 0.30). Convert (cx, cy, w, h) → corner coordinates (x1, y1, x2, y2).
▼
8
Class-wise non-maximum suppression (NMS) drop overlapping duplicates
Multiple grid cells often "vote" for the same object. NMS keeps the highest-score box and discards any other box of the same class that overlaps it by more than NMS_THRESHOLD (default IoU > 0.5). Result: usually 1–3 boxes per object.
▼
9
Un-letterbox undo step 5: model coords → original image coords
Step 5 may have scaled and padded. Each surviving box's corners get the same scaling reversed (and pad offset subtracted) so the rectangle lands on the actual pixel positions of the original image / camera frame.
▼
10
Output depends on which script
det_image_yolov8.py — draws coloured rectangles + class name + score on a copy of the source image, saves to det_result.jpg.
det_live_xy_yolov8.py — picks the highest-confidence box, computes its centre (cx, cy) in original pixels, packs into an 8-byte UART packet [0xAA 0x55 class score xHI xLO yHI yLO], and (if SHOW_DISPLAY) draws the rectangle on the live feed. Repeats at sensor framerate.

Glossary for newcomers

kmodel
A compiled neural network for the K230 chip. Contains the numbers (weights) the model learned during training, plus an execution schedule the KPU follows.
KPU (Kendryte Processing Unit)
The K230 chip's hardware accelerator dedicated to neural network math. Runs convolutions ~100× faster than the CPU.
ai2d
The K230's image-pre-processing hardware. Does resize, crop, pad, format conversion without using the CPU. We use it for the letterbox in step 5.
Letterbox
The trick to feed a non-640×480 image to a 640×480 model without squashing it: scale by the largest factor that fits, then fill the leftover edges with a constant grey.
Anchor / grid cell
YOLO splits the image into cells; each cell may predict one box centered near it. The 6300 candidates in step 6 are these cells across three grid sizes. YOLOv8 "anchor-free" means cells predict boxes directly (no anchor templates), unlike older YOLO versions.
Sigmoid
A function that squashes any number into the range 0–1, used to turn raw network outputs into a probability-like confidence.
NMS
Non-Maximum Suppression. Step 8. Removes near-duplicate boxes pointing at the same object.
histeq / histogram equalization
Pixel-intensity remapping that makes a photo's histogram closer to uniform — boosts contrast. Step 3.
NCHW
Memory layout for a 4D image tensor: Batch, Channels, Height, Width. Step 5's output is (1, 3, 480, 640) in NCHW.
int16 activation
Internal numbers inside the kmodel are stored as 16-bit integers (vs 8-bit). Twice the precision, slightly bigger model, much better at preserving small confidence differences — why we picked the kld_i16act_u8w_calib74 variant.

Generated for the K230-RescueLine project. Pipeline verified against PC simulator on data/calibration_74/ images: top-3 detections come back with smooth scores in the 0.6–0.85 range and IoU ≈ 0.85 vs ground truth.
