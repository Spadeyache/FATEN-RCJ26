Setting up on a new PC

From bare machine to artifacts/deploy/ SD-card bundle. Every step you actually have to type, in order, with what to expect at each one.

Before you start

The path

1

Get the code onto the new PC

Either clone (if it's in git) or copy the whole k230/ tree. Keep the structure intact — paths inside the pipeline are relative to it.

# option A — git
git clone <your-repo>
cd RoboCupJunior_RescueLine/k230

# option B — zip from old PC
# (on old PC)
Compress-Archive -Path C:\...\RoboCupJunior_RescueLine\k230 -DestinationPath k230.zip
# transfer, then on new PC: extract anywhere
After this step you should have k230/docker/, k230/pipeline/, k230/data/datasets/, and k230/train/ all present.
2

Verify Docker works

docker --version
docker compose version
docker run --rm hello-world

If the last line prints "Hello from Docker!" you're good. If not, install/start Docker Desktop first.

GPU check (only if you'll train): docker run --rm --gpus all nvidia/cuda:12.1.0-base-ubuntu22.04 nvidia-smi — should show your card.

3

Build the Docker images

One-time cost. The nncase image takes ~5 min. The train image pulls a ~6 GB ultralytics base — 10 min on fast internet, an hour or more on slow.

cd k230/docker
docker compose build nncase            # always needed
docker compose build train             # only if training on this PC
Tip: if you don't need to train (you have a best.pt already), skip the train build. The convert+eval+deploy half works with just the nncase image.

5

Run the pipeline

Three equivalent runners — pick whichever fits your shell. They all do the same thing.

# --- Windows PowerShell ---
cd k230\pipeline
.\run.ps1 all                  # full path (needs train image + GPU)
.\run.ps1 all-skip-train       # skip training, use existing best.pt
.\run.ps1 calibrate            # one stage at a time
.\run.ps1 compile
.\run.ps1 eval

# --- Linux / Mac / Git Bash ---
cd k230/pipeline
chmod +x run.sh                # first time only
./run.sh all
./run.sh all-skip-train
./run.sh calibrate
./run.sh compile
./run.sh eval

# --- If you have GNU make installed ---
cd k230/pipeline
make all
make all-skip-train
make calibrate compile eval

Each stage prints what it's doing and what it produced. If one fails, fix it and re-run just that target — earlier stages don't redo work.

Tested: .\run.ps1 calibrate and .\run.ps1 select verified working on Windows PowerShell 5.1 + Docker Desktop. Stages 03 → 07 measured end-to-end (see artifacts/reports/variant_matrix.csv).
6

Check the matrix

cat artifacts/reports/variant_matrix.csv
cat artifacts/reports/winner.txt

You're looking for avg_best_iou ≥ 0.75 and recall@IoU0.5_score≥0.05 ≥ 0.95 on the winning variant. If both variants fail to clear that, your training is the problem, not the quantization — go back to stage 01.

Expected on the included dataset: i16act_u8w wins with ~0.80 IoU, ~0.99 recall.

7

Flash the K230D

The package stage produced artifacts/deploy/ — copy all 6 files to the K230D SD card at /data/k230-deploy/.

artifacts/deploy/
├── model.kmodel             ← the compiled detector
├── deploy_config.json       ← labels + thresholds
├── det_image_yolov8.py      ← single-image inference
├── det_live_xy_yolov8.py    ← live camera + UART
├── yolov8_decode.py         ← shared decoder
└── README.md

Then on the CanMV REPL:

import det_image_yolov8
det_image_yolov8.detection()

# live camera:
import det_live_xy_yolov8
det_live_xy_yolov8.live()

What "done" looks like

  • ✓ artifacts/exports/ contains at least one model.kmodel (~3 MB)
  • ✓ artifacts/reports/variant_matrix.csv has IoU ≥ 0.75 on at least one row
  • ✓ artifacts/reports/winner.txt names a variant
  • ✓ artifacts/deploy/ has 6 files totaling ~3.4 MB
  • ✓ On the K230D, det_image_yolov8.detection() draws bounding boxes on the test image

When something breaks

"docker compose build" hangs with no output

BuildKit progress is TTY-formatted and gets eaten by some shells. Use:

DOCKER_BUILDKIT=1 docker build -f Dockerfile.train -t k230-train:latest --progress=plain .

"nncase.simulator.k230.sc: not found" in eval

PATH not set inside container. The Makefile handles this automatically; if calling stages by hand, prepend:

export PATH=/usr/local/lib/python3.10/dist-packages:$PATH

"ModuleNotFoundError: cv2" or "yaml"

Not baked into the nncase image. Install inside the container:

docker exec k230-nncase pip install --quiet opencv-python-headless pyyaml

Train fails with "DataLoader worker killed by signal: Bus error"

PyTorch DataLoader workers ran out of shared memory. Docker's default /dev/shm is 64 MB. The docker-compose.yml in this repo already sets shm_size: '8gb' for the train service — if you customized it, restore that line, then:

docker compose down train
.\run.ps1 train       # or: ./run.sh train

Eval recall ≈ 0 with non-zero IoU

Score saturation from uint8 PTQ. Use the int16-activation variant — already in configs/pipeline.yaml as yolov8_kld_i16act_u8w.

K230D shows "silver 638.50" gibberish

The on-device aicube.anchorfreedet_post_process doesn't work for this ONNX export. yolov8_decode.py in the deploy bundle is the working pure-Python decoder — make sure it's on the SD card.
